# Pulsar Fusion Web

针对 **Pulsar Xlite v4 Mini** 的 Web 配置工具，支持本地运行和 GitHub Pages，使用 Chrome / Edge 的 WebHID 直接访问鼠标。基于用户提供的 Fusion 1.0.5.4 安装包静态解包、.NET 反编译及已连接鼠标的 HID 报文验证。没有执行 Windows 安装程序。

## 启动

```sh
npm install
npm run dev
```

在桌面版 Chrome / Edge 打开终端打印的本地地址（默认 `http://localhost:5173`），点击 **连接鼠标**，在浏览器选择器中选择 Xlite v4；使用接收器时选择 **1K Dongle** 或 **8K Dongle**。Safari / Firefox 不提供此处需要的 WebHID。本次本地内嵌浏览器也已完成实机连接；其他内嵌预览若不提供 WebHID 或设备选择器，请使用独立 Chrome / Edge。

无线配置时只需插入接收器，开启鼠标并确认能无线移动光标，无需连接鼠标数据线。接收器连接会先读取配对型号，确认是 Xlite v4 后才允许配置。若连接失败，先唤醒鼠标、关闭其他配置网页/软件，再重新插拔接收器并连接；本次实测中的 HID STALL 在关闭其他会话并重插后恢复，但没有单独确认是哪一个因素导致。

若出现 `Failed to write the feature report`，这是浏览器发送 HID 报告失败的统一提示，不能仅凭这句话断定是网页权限、休眠或占用。连接诊断会保留每个候选通道的报告长度、失败阶段和原始错误；“导出诊断”同时包含浏览器版本与配置通信记录，不记录日常键鼠输入。1K / 8K 普通连接前会先做被动读取，跳过读取失败或不提供 64 字节配置报告的通道，再发起配置查询；接收器状态 `05` 会单独显示为鼠标未响应。

1K 通信遵循原版发送后等待再读取的时序。配对型号查询若发送失败，会在同一连接内做有限恢复（总共最多 4 次）；每次都必须重新查询并验证型号。诊断中的 `identityTries` 记录次数。设置写入不自动重发。

```sh
npm test       # 协议、传输、宏与文件格式校验
npm run build # TypeScript 检查和静态构建
npm run preview
```

生产文件位于 `dist/`，可通过 HTTPS 静态托管。无需账号、服务端或本地驱动桥接程序。配置和本地宏存储于当前浏览器；浏览器授权与存储按站点隔离。

首次授权后，刷新或重新打开同一站点会自动尝试连接已授权且当前接入的支持设备，并读取配置。自动连接不弹出设备选择器；未找到设备时保留离线编辑，连接失败时可点击“连接鼠标”重试。未应用的本地草稿会保留，不会自动写入鼠标。点击“断开”会在当前浏览器的站点存储中关闭自动连接，刷新或重新打开页面后仍保持断开，直到再次手动连接并读取成功；取消选择或连接失败不会恢复自动连接。意外掉线不会更改此偏好。清除站点数据会重置偏好，清除设备授权后需重新手动授权。此流程使用 [WebHID 的已授权设备接口](https://developer.chrome.com/docs/capabilities/hid)。

## GitHub Pages 自动部署

[部署工作流](.github/workflows/pages.yml) 在推送到 `main` 或手动运行时执行：`npm ci` → 测试 → TypeScript/Vite 构建 → 发布 `dist/`。工作流不运行硬件测试，也不上传安装包、设备备份或反编译目录。

在仓库 **Settings → Pages → Build and deployment** 中选择 **GitHub Actions**。当前项目的默认站点地址为 `https://cbingb666.github.io/pulsar-web/`；工作流使用 Pages 返回的路径构建，图片和 JS/CSS 会遵循同一子路径。本地开发仍使用 `/`。

可在本机检查相同的生产路径：

```sh
npm run build -- --base /pulsar-web/
npm run preview -- --base /pulsar-web/
```

Pages 的 HTTPS 地址可满足 WebHID 的安全上下文要求。首次在部署站点使用时需重新授权鼠标；localhost 中保存的草稿不会自动迁移，可用 JSON 导入导出。

私有仓库能否启用 Pages 取决于 GitHub 套餐，参见 [GitHub 官方要求](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。工作流不会改变仓库可见性。

## 已实现

- 读取真实设备配置；常用性能设置即时应用，其他更改暂存确认；写入后回读验证，失败明确提示。
- 6 个设备配置槽位的读取、切换；本地草稿、JSON 配置备份、导入校验。
- 1–6 档 DPI、独立 X/Y、50–32000 DPI、10 DPI 步长、当前档位、各档指示灯颜色。
- 回报率、0–15 ms 消抖、0.7/1/2 mm LOD、Motion Sync、角度捕捉、波纹控制。
- 6 个按键：鼠标、滚轮、键盘组合、DPI、配置循环、多媒体、快捷功能及设备宏；保留至少一个左键。
- DPI 指示灯关闭/常亮/呼吸、亮度和呼吸速度。
- 电量、充电状态、固件版本；30 秒至 15 分钟休眠、低电量阈值。
- 宏录制、键盘/修饰键/鼠标/滚轮/延迟事件、编辑排序、JSON 和原版 Fusion CSV 导入导出。
- 设备宏上传、回读、导入、删除；按键绑定支持一次、指定次数、按住循环、再次按下停止。删除前检查全部槽位中的引用。
- 通信日志和诊断导出；断连、校验和、超时、错位响应、部分写入失败处理。
- 配置恢复和出厂恢复入口有独立确认；出厂恢复发送后断开，并要求重新连接检查状态。

设备标识：有线 `3710:3401`、1K 接收器 `3710:5402`、8K 接收器 `3710:5403`。只有 8K 接收器允许选择 2K/4K/8K 和接收器指示灯模式。1K 接收器已完成实际读取、DPI/回报率、配置切换、电源参数、宏上传及侧键绑定的写入回读和恢复验证。8K 已完成实机配对确认、浏览器配置读取和部分设置写入验证，具体范围如下。

## 8K 接收器配对与实机验证

顶部 **配对 8K 接收器** 可在未连接鼠标时打开。此流程针对原版 `3710:5403` 接收器和 Xlite v4；不包含其他型号、Gen.2 或固件更新。

1. 只插入目标 8K 接收器，拔下其他接收器和鼠标 USB 线，开启鼠标无线模式。
2. 同时按住鼠标左键、右键和滚轮中键 3 秒，直到 LED 闪烁。
3. 点击 **选择 8K 接收器并开始配对**，在浏览器选择目标设备。配对命令仅发送一次，最多等待 30 秒。
4. 接收器报告完成后，网页会重新校验是否为 Xlite v4，并读取配置；本地未应用草稿保留。若浏览器没有同时提供设置通道，关闭窗口后点击 **连接鼠标**，选择 **8K Dongle** 完成检查。
5. 连接成功后，在性能设置选择 2000 / 4000 / 8000 Hz，在电源管理调整接收器灯光；设置仍需设备回读确认。

实现依据官方配对工具 V0.11 / V0.12 的静态反编译，详见 [配对协议证据](docs/receiver-pairing-evidence.md)。配对使用独立 Input/Output Report；设置使用 Feature Report。实机确认一个 8K 接收器的 MI02 和 MI03 具有相同描述符，浏览器无法直接读取其 USB 接口编号。现在对这两个候选各做两次被动 Feature 读取，仅在一侧稳定返回有效配置报文、另一侧稳定返回已知读取失败时选择配对通道；结果不完整或有歧义时停止，不尝试配对写入。该识别已通过生产 TypeScript resolver 与原生 HID 适配器的实机只读检查；用户已报告配对完成，浏览器连接和读取也已验收。

实机抓包确认这台接收器的型号和灯光响应会保留前一查询的地址；灯光写入还可能一直返回上一条完成报文。现已针对已知序列适配，并保持校验和、型号和普通命令的严格检查；灯光命令只发送一次，必须重新读到目标模式才算写入成功。DPI 查询的持续处理中或旧回包有有限只读重试，设置写入不自动重发。电量返回 `255` 时显示未知电量，不将其当作 0% 或休眠。

截至 **2026-10-18**，这台 Xlite v4 Mini 与原版 8K 接收器的验证结果：

| 功能 | 实机结果 |
| --- | --- |
| 配对、普通连接、配置读取 | 用户确认配对成功；修复后浏览器及生产客户端完整读取通过 |
| DPI 修改和档位切换 | 用户确认可用；日志记录了写入后的档位回读 |
| 8000 Hz 配置 | 完整配置读取通过，寄存器回读为 8000 Hz；尚未测量实际 USB 报告频率 |
| 灯光：仅低电量提醒 | 浏览器写入及完整配置回读通过 |
| 灯光：显示连接状态 | 灯光模式及活动配置回读通过；随后完整配置读取曾在 `07/82` 超时，尚未完成整次保存验收 |

8K 支持仍在完善：配对取消/超时等异常场景、所有回报率逐档测试，以及宏、配置切换等完整写入矩阵尚未覆盖。用户反馈 8000 Hz 下 macOS 桌面指针体感偏慢，原因尚未确认；配置回读值不等于实际移动精度或延迟测量。详细证据和未完成项见 [验收记录](docs/verification.md)。开发热更新后若仍重复旧错误，请刷新整页以重新创建连接客户端。

“取消”只停止本页等待并关闭通道；已发送的无线配对命令不能撤回，取消或超时后应重新连接检查状态。配对会改变原有无线连接关系，不会在页面加载或自动连接时触发。“连接诊断 → 导出诊断”包含此次选择的接口描述、只读接口检查、配对输入输出和结果，便于后续实机适配。

## 哪些更改会即时生效

连接并读取设备后：

| 设置 | 保存时机 |
| --- | --- |
| 当前 DPI 档位、回报率、LOD、Motion Sync、角度捕捉、波纹控制 | 点击后直接写入并回读确认 |
| DPI X/Y 数值 | 实际修改后，按 Enter 或离开输入框时写入 |
| 消抖时间 | 松开滑块或调节键后写入；仅聚焦不会保存 |
| 按键映射、DPI 档位增删、颜色和灯光、电源、导入及默认值草稿 | 点击“应用到鼠标” |
| 宏内容 | 点击上传；按键中的宏绑定仍需应用 |

即时操作只提交明确更改的字段，不顺带保存其他草稿。DPI 档位增删或导入尚未确认时，DPI 操作继续暂存，先应用完整布局后才恢复即时生效。离线编辑和重新连接不会自动提交旧草稿。设备配置发生外部变化或写入失败时会停止即时应用，提示重新读取实际设置。

## 验证与边界

实测设备为这台 Mac 上的 Xlite v4 Mini，固件 `00.00.10.16`，已验证有线、1K 和原版 8K 接收器通信；各连接的写入覆盖范围不同。读写证据和范围见 [验收记录](docs/verification.md)。**这是可用的逆向实现，不宣称已经与 Windows 原版 100% 等价。**

尚未覆盖：

- 浏览器无法修改 Windows 指针速度、系统双击/滚轮速度、系统托盘和开机启动，也不能在页面失焦后全局录制键鼠。
- 宏中的鼠标移动轨迹：原生序列化与解析代码的操作码存在矛盾，当前明确拒绝此类事件。长延迟使用多个已确认的 16 位延迟保持总时长。
- 独立 HID 通知接口的实时无线信号与物理 DPI 按键通知尚未接入；点击重新读取刷新状态。
- 8K 配对异常恢复、各回报率逐档验证及实际报告频率测量、灯光模式 1 的完整保存、全部按键动作的实际执行、宏在不同应用中的执行效果、固件刷写和破坏性重置尚未完成实机验收。
- 当前界面为中文 Web 布局，沿用原版资源及功能结构；不是逐像素 WinForms 复制，也未复刻所有语言。

原版 CSV 不保存循环方式；循环方式属于设备按键绑定。CSV 逗号键有原程序自身不转义的问题：可以识别原版导入，但导出该键时会提示改用 JSON。JSON 配置为此 Web 版的附加格式，原版此版本的文件对话框仅发现宏 CSV。

## 项目结构

- `src/protocol.ts`：数据模型、校验、报文构造及按键动作。
- `src/hid.ts`：串行 WebHID 传输、设备配置、宏存储、回读验证。
- `src/receiver-pairing.ts`、`src/ReceiverPairingDialog.tsx`：8K 独立配对通道、状态处理和操作引导。
- `src/macros.ts`、`src/macro-codec.ts`、`src/native-files.ts`：宏编辑模型、原生字节流、CSV。
- `src/App.tsx`、`src/MacroEditor.tsx`：设备页面与宏编辑器。
- `docs/extraction.md`、`docs/native-evidence.md`、`docs/protocol.md`：提取链、源程序证据与协议说明。
- `scripts/`：仅用于开发验证的 macOS/hidapi 诊断工具，Web 应用不依赖它们。
- `.local/`：忽略提交的原始安装包提取内容、反编译结果、工具和设备备份。

可选硬件验证命令默认只读；带 `--write-test` 才执行备份后的临时修改与恢复。不要与其他配置工具同时运行。终止进程、拔线或断电可能中断恢复，原始报文备份在 `.local/`。

```sh
python3 scripts/read-device.py
python3 scripts/hardware-smoke.py --write-test
node_modules/.bin/tsx scripts/hardware-client-smoke.ts --write-test
# 1K 接收器：默认只读；加 --write-test 验证临时修改和恢复
node_modules/.bin/tsx scripts/hardware-client-smoke.ts --product-id=0x5402
```

原版程序及反编译源码不包含在构建产物中。`public/assets/` 的鼠标和品牌图片、`public/favicon.ico` 的应用图标来自用户提供的软件，用于界面复现；权利仍属于原权利人，本项目不授予这些资源的再分发权利。开源参考实现的 MIT 声明保留在 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
